# 本番の動作確認リスト (10/28 の運用開始前)

テスト (単体・ルール・E2E) は Firebase エミュレータで動いているため、**本番でしか起きない不具合** (複合インデックス、ルールの反映漏れ、ブラウザの違い、印刷など) は見つけられません。
運用開始前に、下の順で一通り触ってください。使うのは、学生用の試験アカウント (it_datasharing@trident.ac.jp、名前「テスト」、Cチーム) と、教員のアカウントです。
問題が出たら、**画面に出たエラー文** (または画面の写真) を教えてください。

URL: https://sotsuken-pj.web.app
準備: デプロイが成功していること (Actions の Deploy app が緑)。ブラウザは Chrome か Safari。

## A. 学生アカウント (PC)
1. ログイン → 「はじめに」の案内 → 確認して始める → **利用ガイドが自動で開く** → 「はじめる」で閉じる (次回から自動では出ない)
2. **ホーム**が「読み込み中…」のままにならず、今日のミッション・ありがとう・今日やること・次にやることが出る。エラー文が出たら、その文を控える
3. ヘッダーの **💡 ガイド**が開き、「こんなとき」の場面を開くと手順と「〜を開く」ボタンがある
3b. **初期WBSの見直し**: キックオフしたチームの学生のホームに「最初にやること: 初期WBSの見直し」が出る → 担当のない項目がある間は「見直しを終えた」が押せない → WBSで「担当が決まっていない項目だけ」に絞って担当を付ける → チェックして「見直しを終えた」→ カードが消え、教員のチーム詳細に「終えました」と出る(もう一度見直してもらうで戻る)
4. **WBS**: ふだんは閲覧モード (追加の欄がない) → 「編集モードにする」→ タスクを「テスト @名前 〜11/30」で追加 → 担当・期間・状態を行の中で変える → 削除して「元に戻す」 → 下の「変更履歴」を開くと、いまの操作が (誰が・いつ・何を) 出る
5. **ガントチャート**: 「WBS・ガントチャート」で、一覧の右に棒が出る → 「ガントチャートを大きく」→「ガントチャートで編集する」にチェック → 日付のない行をなぞると期間が入る → バーをドラッグして動く → バーの名前をタップして1日ずつ動かす → 下の欄でタスクを追加
6. **作業ログ**: 結果ボタン (進んだ/完了した/詰まった) → 説明10字以上 → 次にやること → 「＋ WBSにない作業をした」で作業を1つ追加 → 「作業ログを送信」 → WBSに「WBS外の作業(あとから追加)」と「後追い」の印のタスクができる。もう一度開いて「作業ログを更新する」で直せる
7. **ありがとう**: ホームのカードで、名前を押してスタンプを送る → 「今日あとN回」が減る
8. **ホームの下の「チームのようす」**: メンバーの表が出る (「チーム」のメニューはない)。**PJ分析**: 概況・ガントチャート・WBS が出て、「Excelで保存」で .xlsx が落ち、Excelで開ける
9. **PJ分析 → 「ミーティングを始める」**: 4つの段階を「次へ」で進められる。手待ちの人がいれば振り分け案が出る (出ない場合は、全員にタスクがある状態)

## B. 学生アカウント (スマホ)
1. ログイン (Safari/Chrome。LINE等のアプリ内ブラウザは不可)
2. ホーム・WBS・作業ログが読みやすく、メニューが横にスクロールできる
3. **ガントチャート**: タスク名が左に固定される。空の行を**指でなぞる**と期間が入る (横にスクロールしたいときに、なぞった部分が反応しすぎないか)。バーを指でドラッグできる。うまくいかなければ、タップして「−1日/＋1日」で調整できる
4. 作業ログの入力の途中でタブを閉じて開き直しても、内容が残る

## C. 教員アカウント
1. ログインでき、チーム一覧が出る
2. **アクセス** (ナビ): A の手順を学生アカウントで行ったあと、「テスト」の行に**今日**のアクセスが出る。名前を押すと、日ごとの時刻・開いた回数・画面が出る (記録は約2分遅れることがある)
3. **チーム詳細 → PJ分析**: 画面が出る。「PDFで保存(印刷)」→ 印刷画面で**送信先「PDFに保存」・A4・横**: ヘッダーやメニューが入らず、ガントチャートが途切れず、WBS表が見える
4. **ミーティング**: 4段階、タイマー、「事実の確認」の表 (最後に動いた日など)、「ぜんぶ表示」
5. **学生の画面** (プレビュー): テストを選ぶと閲覧のみ。ガイドのボタンが出ない
6. **設定 → 書き出し・バックアップ**: バックアップ (JSON) と CSV (アクセス履歴を含む) が落ちる

## D. バックアップ (Apps Script)
1. Apps Script に最新の `Code.js` を反映する (今回、`accessLogs` を対象に追加した。apps-script/README.md)
2. `backupDaily` を1回実行 → ドライブの「バックアップ」フォルダに今日のファイルができる
3. ファイルを開き、`accessLogs` と `teams/C/thanks` のキーがある
4. フォルダの共有が「制限付き」のまま

## E. 利用量
- Firebase コンソール → Firestore → 使用状況で、読み取り・書き込みの数を見る。学生数人で上の手順をしたあと、**1人あたり何回読んだか**を控える。28人 × その数が 5万/日 (無料枠) の半分以下か
- 目安: 1人あたり 1日 700 回以内
- エミュレータでの計測 (2026-10-24、28名・各チーム60タスク・作業ログ30日ぶんの規模): 学生1人が1回アプリを開いてホーム→WBS→作業ログ→ミーティングと回ると約100回。教員のダッシュボード初回が約750回、アクセス履歴が約400回 (最大でも約600回)。これを本番の実測と比べる
