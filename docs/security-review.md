# セキュリティ確認 (2026-10-22)

権限の境界は Firestore Security Rules のみ(バックエンドなし)。rules・クライアント・ホスティング設定を確認した。

## 確認した点(問題なし)
- ログイン: メール確認済み かつ `@trident.ac.jp`(完全一致。サブドメインは不可) かつ roster 登録済みでないと、どのデータも読めない
- 学生は他チームの tasks / dailyReports / meetings / comments を読めない。名簿は自分の文書だけ読める(一覧不可)
- 教員専用(teacherNotes / followups / evaluationsRaw)は学生から読み書きできない
- 学生は、roster・teams・comments・milestones・config を書き換えられない。欠席は教員のみ
- タスクは物理削除不可(ソフトデリートのみ)。`updatedBy` は自分に固定。`createdBy` は変更不可
- 作業ログは、自分の分・当日のみ作成/編集。教員が欠席にした作業ログは学生が直せない

## 見つかった問題と対処
| # | 内容 | 影響 | 対処 |
|---|---|---|---|
| 1 | 作業ログの `dayKey` を今日にしたまま `date` を過去の日付にすると、過去の授業日の作業ログを後出しで作れた(rules が `date` を検査していない) | 「当日のみ」の趣旨が崩れ、未提出の検知を逃れられる | `date` が今日であることをルールで検査(`dateKey()`)。ルールのテストを追加 |
| 2 | タスクのリンクが、保存済みURLをそのまま `href` にしていた。画面は `http(s)` のみ受け付けるが、ブラウザのコンソールから直接書くと `javascript:` を保存でき、チームメンバーや教員がクリックすると実行される | 保存型XSS(教員は全データを読めるため影響が大きい) | 表示時に `http(s)` 以外はリンクにしない(チームの共有フォルダURLは元から検査済み) |
| 3 | ホスティングにセキュリティヘッダーがなかった | クリックジャッキング等 | `X-Content-Type-Options` / `X-Frame-Options: DENY` / `Referrer-Policy` / `Permissions-Policy` を追加。`index.html` は no-cache |

## 既知の残り(許容)
- 学生はタスクの `detail`、作業ログの `entries`、ミーティング記録の本文を、サイズ上限(1ドキュメント1MiB)内で自由に書ける。同じチーム内・教員への表示のみで、React が文字列をエスケープするため、実害は小さい
- 学生は、同じチームのタスクを(ソフトデリートも含め)直せる。これは運用上の決定(チーム全員が編集可)
- Content-Security-Policy は付けていない。Googleログインのポップアップ/リダイレクトを壊す恐れがあり、本番で確認できないため。運用開始後、落ち着いてから追加を検討
- 利用量の上限(Spark 無料枠)を超えると読み取りが止まる。想定は 5万/日 に対し 約2万/日
- サービスアカウントのキー(GitHub シークレット)は、運用が安定したら削除する
