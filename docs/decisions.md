# 卒研進捗管理アプリ 決定事項 (2026-10-21 時点)

教員との合意事項。実装・設計はこの内容を前提にする。変更があれば追記する。

## 目的と方針
- 進捗の見える化 / 学生の負荷を抑えた報告 / 偏り・停滞の早期発見 / 教員の管理負担の軽減。
- 学生を監視するツールにしない。ランキング・作業時間計測・点数化はしない。
- 教員は全チーム・全員の情報を見られる (学生に明示する)。教員専用メモは学生に見せない。

## 対象
- トライデントコンピュータ専門学校 高度情報学科3年 ST1、28名、A〜Hの8チーム。
- 名簿は **苗字のみ** (同姓は区別用に1文字付ける) + メールアドレス + チーム。フルネームは保存しない。
  - A: 岩田・近内・竹中・森 / B: 長田・島尻・TAY・松下 / C: 浅野・今井・五味田 / D: 小林・髙瀬・徳松
  - E: 安藤・広田・國枝・山崎 / F: 井上・鈴木秀・山本 / G: 入口・黒畑・石橋・鈴木空 / H: 磯・水谷・村岡
- 実データ (メールアドレス等) はリポジトリに入れない。アプリの教員画面からCSVで登録する。登録後の修正 (苗字の変更・チームの変更・名簿から外す) と、教員の表示名の変更は、教員画面から行う。チームを変えると学生IDも新しい番号になり、日報・担当は元のチームに残る。名簿から外すと、その学生はログインできなくなる (データは消えない)。

## 認証・権限
- ログインは Google (@trident.ac.jp) のみ。Security Rules で email ドメインと email_verified を検証し、名簿 (許可リスト) にあるアカウントだけ読み書き可。
- 学生は自チームのみ閲覧・編集。他チームは見えない (切り替え機能も作らない)。
- 教員は全チーム閲覧。教員専用メモ・評価の元データは学生から読めない別コレクションに置く。

## 機能
- WBS/タスク: 階層3段まで。項目は タイトル・担当(複数/空欄可)・開始/終了予定・状態(未着手/進行中/完了/保留)・詳細・リンク。
  親の完了率は子から自動計算。1行入力で追加、一括貼り付け(インデント=階層)。チームの誰でも編集・削除可。
  削除はソフトデリート + 元に戻す (確認ダイアログは出さない)。作成者・最終更新者を記録。
- 日報: 授業日のみ。**運用開始は 2026-10-28 (水)**。それより前の授業日 (10/27 など) は、未提出の判定・提出状況の表・欠席の入力の対象にしない (設定 `dailyStartDate` で変更可)。今日触ったタスクのチェック+**一言 (選んだ項目ごとに必須)**、固定項目 (調査・勉強 / チームで相談 / その他。これも一言必須)、困っていること(任意)。一言のないチェックだけの項目は提出に数えない。入力の強制は画面側 (ルールではリストの中身を検証できない)。
  提出した日のうちだけ編集可 (日本時間0時で固定)。「欠席」にできるのは教員のみ。時間記録はしない。
  チーム内の日報閲覧は初期ON、教員が切り替え可。
- ミーティング: 毎週木曜2限 (11:15-12:45)、1チーム10分×8。学生と同じディスプレイを見ながら行う。
  共有画面には学生に見せてよい情報だけ。教員専用画面は別URL。チームの順番は毎週回す設定あり。
  記録 (決まったこと・次のアクション) の入力は初期は教員のみ。チームごとの設定で「チームも入力可」に切り替え可。
- 議事録: MVP は手入力のみ。録音の取り込みは運用開始後 (録音ファイルはアプリに保存しない。教員PCで文字起こし→テキストを取り込む。全文は教員のみ、要約は確認後に公開)。
- 企画: 企画の内容 (概要・技術など) はアプリに入力・保存しない。採用企画名 (1行) のみ記録する (不採用の記録は要確認)。
- キックオフ: 教員がチーム詳細の「キックオフ」で、採用企画名の記録 / WBS雛形の適用 / 叩き台タスクの取り込み (任意) / 状態を「進行中」にする / 共有フォルダURL登録 (任意) を行う。キックオフ前のチームの学生画面は「企画検討中」表示。
- 叩き台タスク: 企画決定 (10/29) 後に、教員が提供する企画発表資料 (PDF) をもとに Claude Code が採用企画ごとに作成し、教員が確認してから教員画面のインポートで各チームのWBSに取り込む。アプリ内での自動生成 (LLM API) は費用の面で行わない。
  形式: 6大項目の下に1企画50〜60項目、各項目に詳細 (やること / できあがりの目安のみ。ヒントは書かない)。担当・日程は空欄。「叩き台」と分かる印を付け、学生は自由に追加・削除・変更できる。機材発注 (11/5・12/1) に関わる項目はハード系企画に含める。
  PDF・名簿など個人名を含む資料はリポジトリにコミットしない。
- WBS雛形: 共通の6大項目のみ (企画の具体化 / 要件定義 / 外部設計 / 内部設計・実装 / テスト・検証 / 発表・展示準備)。各大項目に1〜2行の説明。
- マイルストーン: 共通・チーム固有とも教員のみが編集。学生は閲覧のみ。
- 評価: FIXER社の評価は学生に見せない。学生の相互評価は匿名で集計して公開 (教員が確認して公開、自チームの回答は除外)。評価者の識別情報は教員のみ。CSV取り込みは運用開始後。
- 成果物: アプリにファイルは保存しない。チームごとの共有DriveフォルダのURL (教員が登録) と、タスク詳細に貼るリンクのみ。
- コメント: 学生に公開 / 教員専用 の2種。日報には付けず、タスクとミーティング記録に付ける。
- 通知: Apps Script + Gmail (教員アカウントから)。授業日のみ。火・水 16:30ごろ、木 10:45ごろ。
  **10/28(水) から、初日の16:30のリマインドを本番 (goLive) で行う** (16:15ごろに dryRunAfternoon で送る相手を確認してから goLive。初回の実行後、教員宛の送信結果メールと、学生1名への到着確認を行う)。トリガーの起動は 10/22 に確認済み。
  実装は `apps-script/` (手順は README.md)。Firestore REST を教員アカウントの権限で読む。初期は試験モード (教員宛に1通だけ)、確認後に `goLive` で学生に送る。未提出が0名のときは何も送らない。二重送信の防止と、送信先40名超での停止がある。
- 日本語UI。PCとスマホ。確認ダイアログは極力出さない。

## 技術
- Vite + React + TypeScript、Firebase (Hosting / Authentication / Firestore)、無料プラン (Spark)。支払い情報は登録できない。
- Cloud Functions / Storage / 自動バックアップは使えない。バックアップは、(1) 毎日、Apps Script が教員の Google ドライブ(非公開)に JSON を保存 (60日分)、(2) 教員画面の「書き出し」(JSON + CSV 6種。ブラウザ内で作成)。復元は、書き出しページの「バックアップから復元する」(同じ id の文書を上書き、バックアップにない文書は消さない。直前の状態を自動でダウンロード)。GitHub のリポジトリは公開 (public) なので、データのバックアップを Actions の成果物などに置かない。
- Firebaseプロジェクトは yoichiro.takikawa@trident.ac.jp (学校の個人アカウント) で作成。共同オーナーに別の教員を追加。
- Firestore のロケーションは asia-northeast1。Googleログインは学生アカウントでも通る見込み (要・学生での確認、`login-check/`)。
- 既存の Express+SQLite の試作 (`server/`, `client/`) は破棄して作り直す予定。
- デプロイは GitHub Actions (手動実行) で行う。サービスアカウントの鍵は GitHub リポジトリのシークレット `FIREBASE_SERVICE_ACCOUNT` に登録する (Claude Code の環境変数は全員に見えるため使わない。チャットにも貼らない)。ワークフローは `.github/workflows/`。運用が落ち着いたら鍵を削除する。

## 関与・貢献の見える化とアメ・ムチ (2026-10-22 決定)

- 目的: サボりを仕組みで防ぎ、関与度・貢献度・積極性を把握する。同時に、学生がアプリを使うのを楽しめる仕組みと、負担を下げる仕組みを入れる。
- 関与の指標 (直近3週間): 日報の提出と連続日数、日報で触れたタスク数、担当・完了・期限超過、ミーティングの約束 (担当者付き) の達成、ありがとうの送受信。**チーム内の全員に見せる** (日報は、設定でチーム内の閲覧がオフなら自分の分だけ)。順位や合計点は出さない。
- 教員の評価記録 (関与度・貢献度・積極性) は、**成績の参考資料**。点数の自動換算はしない。数字を稼ぐ行動 (ボタンを押すだけの見かけの貢献) を誘発しないため。教員向けの注意の目安は、教員画面だけに出す。
- アメ: ありがとう (1日3回まで、送った本人と教員が取り消せる)、タスク完了・日報提出の演出 (動きを減らす設定では紙吹雪を出さない)、連続提出、配色の切り替え (5種類。選んだ配色は端末に保存)。
- 負担軽減: 今日自分が更新したタスクを、日報で先に選んでおく。前回の未完了の約束の引き継ぎ。
- 親タスク (子のあるタスク) には担当を付けない。親の状態は、子の状態から自動で決める (保留の子は除く。すべて完了→完了、すべて未着手→未着手、それ以外→進行中)。保存済みの親の状態・担当は無視する (画面と集計で、子から求める)。日報の候補・担当の集計・要確認は、子のないタスクだけが対象。
- ガントの稲妻線: 予定の期間に入っているのに「未着手」のタスクは、開始日の位置まで左に折れる (遅れ)。開始日より前に「進行中」にしたタスクは開始日の位置まで、終了日より前に「完了」したタスクは終了日の位置まで、右に折れる (先行)。それ以外 (進行中・保留・期限内の完了・日付なし・まだ始まっていない未着手) は、今日の線の上 (進行中は、進み具合の入力がないので、予定どおりとみなす)。子が表示されている親の行には点を打たない。
- 日報・WBS・ホームの作り直し (2026-10-23): 日報は、タスクごとのカードで「進んだ/完了した/詰まった」を押して、何を・どこまでやったかを **10字以上** で書く。「次にやること」(10字以上) も必須。提出すると、結果に合わせてタスクの状態も更新 (完了した→完了、進んだ/詰まった→未着手なら進行中)。詰まった内容は、困っていることにも自動で載る。入力の途中は、端末に自動保存。文字数の下限は `src/lib/daily.ts` の MIN_NOTE_CHARS / MIN_NEXT_CHARS。提出の判定 (未提出の検知など) は、これまでの日報との互換のため、一言があれば成立のまま。
- ホームは「今日やること」(期限超過・進行中・予定の期間内のタスクと、自分の約束。1タップで着手・完了) と「次にやること」(前回の日報の次にやること・これから始まるタスク・担当がいないタスク→「担当する」) を出す。
- WBS: 担当・期間は、行の中で1タップで変える。タスク追加は「名前 @小林 〜11/30」で、担当と期限も同時に決まる。
- 卒研は、困ったら先生に相談する性格の授業ではなく、**チームで相談して進める**もの (2026-10-23)。「先生に相談したいこと」の欄、先生への相談を促す文言、「困っていること」2回連続のフラグは設けない。日報の「詰まった」は、チームで解決するための材料としてミーティングに出す (「詰まっていること」)。旧データの blocker フィールドは残るが、画面には出さない。
- まだ作っていない: 教員の月次評価記録 (5段階+コメント)、相互評価の取り込み、今週のハイライト。

## ミッション・WBS外の作業・ガント編集・報告書 (2026-10-23 決定)

- 目的: 学生が日々アプリを使い、WBSを実態に合わせて維持するようにする。WBSにない作業をしても記録に残るようにし、チーム開発の実態をつかめるようにする。企業への中間報告の成果物 (WBS・ガント・概況) を出力できるようにする。
- ミッション (ホーム): 個人の「今日のミッション」(担当タスクに期間を入れる / 今日の作業をWBSに反映する / 日報を提出する) と、チームの「今週のミッション」(全員が今週WBSを更新 / 期間のない未完了タスク0 / 期限超過0 / WBS外の作業の整理)。すべてタスク・日報のデータから求める (達成のための書き込みはしない)。点数・順位は出さない。全部達成した日は1日1回だけ演出 (端末に記録)。`src/lib/missions.ts`。
- WBSにない作業: 日報の「＋ WBSにない作業をした」で、名前・入れる場所・結果・説明を書くと、提出と同時にタスクを作る (担当=本人、source='adhoc'、開始日=今日、完了なら終了日=今日)。入れる場所を選ばなければ、チームに1つの大項目 `adhoc-root`「WBS外の作業(あとから追加)」の下。WBSで「後追い」の印を出し、関与の表に「WBS外」の件数を出す。rules の source は 'user' | 'draft' | 'adhoc'。`src/lib/adhoc.ts`。
- ガントの直接編集 (「ガントで編集する」): 葉のタスクのバーをドラッグで移動、両端で期間変更、日付のない行をなぞって期間入力 (タップだけなら1日)。バー・行名のタップで下のパネルが開き、状態の変更、±1日、担当、タスク追加 (「名前 @担当 〜期限」)。親の行は自動のため編集しない。従来の「日付を入力する」一覧も残す。教員の「学生の画面」プレビューは、チェックボックスが無効なので編集できない。`src/lib/ganttDrag.ts`。
- 報告書 (学生はナビ「報告書」、教員はチーム詳細のタブ): 概況・分析・ガント・WBS。Excel (.xlsx。概況/WBS/ガントの3シート。exceljs をボタンを押したときだけ読み込む) と、PDF (ブラウザの印刷。A4横)。教員専用のデータ (教員メモ・評価) は含めない。
- プロジェクト分析 (`src/lib/analysis.ts`): 進捗の実績と予定 (期間の終了日が今日以前の割合)、期限超過、期間なし・担当なし、担当の偏り、WBS外の作業の割合、次のマイルストーンまでの必要ペースと直近2週間のペース、大項目ごとの進捗、所見。ミーティング画面 (「プロジェクト分析」) と報告書に出す。

## ありがとうの使いやすさ・進捗確認会議の進め方 (2026-10-23 決定)

- ありがとう: ホームに「ありがとう」カードを出す。スタンプ (助かった・ナイス!・おめでとう・がんばってるね・いい考え) を1タップで送れる。最近ほかの人が完了した・WBSに足したことを「伝えるきっかけ」として出す。もらったありがとうは、新着を目立たせ、開いたときにお祝い。1日の上限は3回から5回に。毎日のミッションに「ありがとうを送る」、週のミッションに「全員が今週送る」を追加。ミーティングに「今週のありがとう」。言葉を添えたいときは、従来どおり「チーム」から。
- 進捗確認会議: 1チーム10分を4段階 (前回の約束2分→事実の確認3分→詰まり・手待ちの解消3分→決める2分) に分け、ミーティング画面を段階ごとに出す。docs/meeting-guide.md。
- サボりの客観的な把握: 「事実の確認」に、メンバーごとの最後に動いた日・7日の更新/完了・日報・期限超過・約束を、チーム全員に見せる。評価の言葉は使わず、記録された事実から「N日間、更新も日報もありません」などの気づきだけを出す。
- 手待ちの振り分け: いま取り組めるタスクがない人を見つけ、担当のいないタスクや抱えすぎの人の未着手タスクを案として出し、ワンタップで担当にできる (一緒にやる/引き継ぐ)。

## アクセス履歴 (2026-10-23 決定)

- 目的: 教員が、学生がアプリをいつ・どの画面で使ったかを把握する (サボりを客観的に把握する材料の一つ)。
- 記録する内容: `accessLogs/{日付}_{学生ID}` に、日付・チーム・初回/最終の時刻・開いた回数 (visits。タブを開いてから閉じるまでを1回)・画面の表示回数 (views)・画面の種類ごとの回数 (screens)。入力内容・クリックなどの操作の詳細・作業時間は記録しない。画面の表示は2分ごとにまとめて書く (書き込みを増やさない)。
- 権限: 学生は自分の今日の分だけ書ける (数は増える方向にだけ)。**読めるのは教員だけ**。教員のアクセスやプレビューは記録しない。
- 透明性: 初回の案内に、アプリを開いた記録があり先生だけが見られることを明記し、確認済みの印のキーを更新して**全員にもう一度**表示する。使い方にも記載。
- 画面: 教員のナビ「アクセス」。学生ごとの最終アクセス、直近14日 (授業日に印)、日数、よく見る画面、日ごとの詳細。チームで絞り込み。
- バックアップ・復元・CSV に含める (教員専用データ)。試運転のリセット (reset-pilot) で、そのチームの分も消す。
- 限界: ブラウザを開いていても画面を見ていない時間は分からない。複数端末は合算される。

## 学生向けの利用ガイド (2026-10-23 決定)

- 初回ログイン (案内の確認のあと) に「はじめてのガイド」(7段階) を一度だけ自動で出す。確認済みの印は端末ごと (`guide-seen:メール`)。
- あとから、学生のヘッダーの「💡 ガイド」でいつでも開ける。開いている画面に合わせた段階から始まる。「こんなとき」タブで、場面 (作業を始める/終えた/WBSにない作業/手が空いた/予定が遅れそう/詰まった/日報の書き忘れ/ありがとう/報告書/スマホ) から、手順と画面への移動を探せる。
- 内容は `src/lib/guide.ts`。画面やボタンの名前を変えたら、ここも直す。教員の画面とプレビューには出さない。

## 日報は「前回の日報のあと」の作業を書く (2026-10-24 決定)

- 日報は授業のときにだけ書く。卒研の作業は授業時間外にも行うのが通例なので、日報には、その日の作業だけでなく、**前回の日報のあとにやったこと (授業時間外を含む)** をまとめて書く。
- 日報の日付 (date) は、これまでどおり、書いた授業日の1つだけ。当日中の編集・過去日の禁止も変えない。
- 画面: 「前回の日報(日付)のあとに、やったこと」。前回の日報を出した時刻より後に、自分がWBSで更新したタスクを、先に選んでおく (前回の日報がなければ7日前から)。「WBSにない作業」には「やった日」を付けられ (前回の日報の日〜今日)、その日付がタスクの日付になる。
- ミッション「今日の作業をWBSに反映する」は、「作業の進み具合を、WBSに反映する」に。判定 (今日、自分がタスクを更新した) は変えない。
- ガイド・使い方・配布文の説明を、この運用に合わせた。

## 日報の間があいたときの、やさしい促し (2026-10-24 決定)

- 前回の日報のあと、日報が出ていない授業日 (欠席を除く、今日は含まない) が2回以上になると、本人のホームと日報の画面に、黄色のやさしいお知らせを出す。4回以上だと、少し丁寧な文言 (チームに相談してみる、を添える)。出し終わる (または今日が欠席になる) と消える。`src/lib/dailyNudge.ts`。
- 強い警告にはしない: 「警告」「必ず」などの言葉を使わない (テストで確認)。学生本人にだけ出し、教員向けの要確認 (2回連続の未提出) とは別。

## お気に入りへの追加のボタン (2026-10-24 決定)

- ブラウザは、ブックマークを、ボタンから自動で追加させてくれない (仕様)。代わりに、次を出す: Chrome・Edge 等で「ホーム画面に追加」(beforeinstallprompt のインストールの案内。受け入れられると、案内は出なくなる)、iPhone・Android で「追加のメニューを開く」(共有メニュー。お気に入り/ホーム画面に追加を選べる)、パソコンは Ctrl/⌘ + D の案内。
- そのため、manifest (`public/manifest.webmanifest`) とアイコン (192・512) を追加。サービスワーカーは入れない (更新が古いまま残る事故を避ける)。ブラウザによっては、サービスワーカーがないと「インストール」のボタンが出ない場合があり、その場合は、メニューまたは Ctrl/⌘ + D の案内になる。

## ホームの「チームの今週のミッション」を既定で閉じる / 復元とアクセス履歴 (2026-10-24 決定)

- ホームを縦に長くしないため、週のミッションは既定で閉じる (見出しと達成の数は見える)。開き方は端末に覚える。個人の「今日のミッション」は、これまでどおり開いたまま。
- 復元で、アクセス履歴が停止する問題を修正: 学生が使っている最中にバックアップを復元すると、アクセス履歴の数が食い違い、教員が書こうとして拒否されて、復元が途中で止まった。rules で、教員が accessLogs を (形が正しいものに限り) 書けるようにした。

## トーン (画面の雰囲気) の切り替え (2026-10-24 決定)

- 学生は子ども扱いを嫌うので、既定を「落ち着き」にする (絵文字・感嘆符なし、角の小さい見た目、紙吹雪なし)。配色の既定は「ブルー」。
- 「親しみやすい」を選ぶと、従来の雰囲気 (見出しに絵文字、明るい達成の知らせ、紙吹雪、丸みのある見た目、スタンプは「ナイス!」など) になる。配色と同じく、端末のブラウザにだけ保存する (`src/lib/tone.ts`)。
- 実装: ルートの `data-tone`。絵文字は `<Em>` で、落ち着きでは CSS で隠す。達成の知らせ・スタンプの文言は `say` / `stamps()`。新しい文言を足すときは、両方のトーンを用意する。

## トーンは3種類 (標準・カジュアル・シンプル) (2026-10-24 決定)

- 前のトーン (落ち着き・親しみやすい) を、標準・カジュアルに改め、シンプルを足した。以前の保存値 (calm・friendly) は、標準・カジュアルとして引き継ぐ。既定は標準。
- 標準: 絵文字・感嘆符なしの丁寧語、角の小さい見た目。カジュアル: 見出しの絵文字・明るい言い方・紙吹雪・丸み。シンプル: 飾りのない平らな見た目 (白地・細い枠・影なし・グラデーションなし)、短い言い方、スタンプも文字だけ。
- 利用ガイドも、トーンに合わせて言い方が変わる (`src/lib/guideTone.ts`)。段階・場面の id、移動先、画面名・ボタン名は共通。テストで、段階・場面の数と移動先が揃っていること、標準とシンプルに感嘆符・絵文字がないこと、主要なボタン名が全トーンに入っていることを確かめる。
- 学生向けの使い方ページ (Help) も、トーンに合わせて言い方が変わる (`src/lib/helpContent.ts`。項目の id・見出し・ボタン名は共通。テストで確認)。教員向けの使い方は、トーンでは変えない。
- 新しい文言を足すときは、3つのトーンを用意する (達成の知らせ・スタンプ・日報のお知らせ・ガイド・学生向けの使い方)。

## デスクトップ用ショートカット (2026-10-24 決定)

- ブラウザは、デスクトップにファイルを直接作れない。パソコンでは、お気に入りのカードに「デスクトップ用ショートカットを保存」を出し、ショートカットのファイル (Windows: .url、Mac: .webloc。中身は、このアプリのURLだけ) をダウンロードさせ、デスクトップにドラッグしてもらう。`src/lib/shortcut.ts`。
- Chrome が .url を「危険なファイル」と警告することがあるので、押した後の案内に、URLだけが入った小さなファイルで、「保持」でよいことを書いた。
- Chrome・Edge の「ホーム画面に追加」(インストール) が出る環境では、そちらも使える (スタートメニュー・デスクトップにアイコンができることが多い)。

## WBSとガントの統合・今日のミッションの開閉 (2026-10-24 決定)

- ナビを「WBS・ガント」ひとつに。ふだんは、WBSの一覧の各行の右に、期間の棒 (ガント。今日の線・週の目盛り) を並べる (幅1100px以上)。狭い画面では、棒は出さない。ドラッグで直す・マイルストーン・稲妻線は、切り替えボタン「ガントを大きく(ドラッグで編集)」で、従来のガントを出す。旧URL /gantt は、その表示で開く。教員のチーム詳細も、同じ「WBS・ガント」タブ。`components/WbsGantt.tsx`。

## 「日報」を「作業レポート」に・状態の更新は作業レポートだけ (2026-10-24 決定)
