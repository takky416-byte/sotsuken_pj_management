# 卒研の成果物 (叩き台に、必ず入れる)

教員から共有された、あらかじめ決まっている成果物の一覧 (2026-10-26)。初期WBS(叩き台)は、これを背骨にして作る。
中身は `app/src/lib/deliverables.ts`。叩き台の点検 (`npm run check-draft`、キックオフ画面) が、抜けを誤りとして知らせる。

## 中間報告までの成果物 (中間報告は対面レビュー = 11/25 の外部設計レビューとみなす)
設計書類 (事前送付):
- 要件定義書 / 画面レイアウト / 画面遷移図 / 機能仕様書 / ER図 / テーブル定義書 / 回路図 / システム構成図

試作品:
- 中間報告の際に見せられるもの

## 最終報告までに用意するもの (最終報告はプレゼン方式 = 1/26 の最終レビューとみなす)
- 発表スライド (事前送付)
- 最新化した設計書類 (事前送付)
- デモンストレーションの準備 (当日にデモを見せられない場合は、デモ動画)

## 卒展 (2/6) までに用意するもの
- 操作説明書 / 卒展のシフト表 / アプリ説明用スライド / アプリ説明動画 / 動画のYouTube限定公開 (1/27締切) / 卒展用パネル / ソースコード一式(卒展までに提出。2026-10-26 追加)

## 叩き台での扱い

- 事前送付は、報告の1週間前 (確定): 中間報告 11/25 の1週間前 = 11/18、最終報告 1/26 の1週間前 = 1/19。
- ハード系の企画で、ER図・テーブル定義書がいらない (データベースがない) ときは、点検の「ソフト系」の扱いで外れる。両方ある企画は、両方入れる。
- 題名は、成果物の名前を使う (「ER図を描く」「卒展用パネルを作る」など)。点検が、題名の言葉で見つける。

## 記入サンプルから分かったこと (2026-10-26。「記入サンプル」の5チームぶん: C・D・E・F・G)
サンプルは、前年度の5チームの提出物一式(フォルダ25ST1C・25SF1D・25SF1E・25ST1F・25SF1G。ハード、ソフト、両方の企画がある)。氏名が入っているので、リポジトリには入れていない(要点だけ書く)。
**最初に私が読んだのは、25SF1D(D)だけだった。** 残りの4チームは、あとで一覧を取り直して確認した(ファイルの一覧が、ページに分かれていたため)。

- **提出物の一式(チームごとのフォルダ)**: 設計書類(Excel、番号つき)と、企画説明のスライド、操作説明書(PDF)、アプリ説明動画(mp4)、限定公開URLのテキスト、対応当番シフト表。
- **設計書類は、Excelの定型の用紙に記入する形**。1シートごとに、上の見出しに「論理名称・物理名称・システムID・システム名称・改訂日・改訂者・備考」がある。番号つきのファイル名: 01要件定義、02画面レイアウト、03画面遷移図、04機能仕様書、05ER図、06テーブル定義書、07回路図、09システム構成図(**08は、欠番**。そのドキュメントは、もともとない)。
- **当てはまるものだけ作る**: 05ER図・06テーブル定義書は、データを保存するチーム(CとF)だけ。07回路図は、ハードのチーム(D・F・Gなど)。ソフトだけのチームは回路図なし、データを保存しないチームはER図・テーブル定義書なし。要件定義、画面レイアウト、画面遷移図、機能仕様書、システム構成図は、全チームにある。
- **01 要件定義**: 機能要件を番号つきで、1つずつ「どのような機能か」「入力・表示・処理は何が必要か」を書く。ハードとソフトは、別のシートに分けて書く。
- **02 画面レイアウト**: 画面ごとに1シート。「項目名称 / 入力か表示か / 種類(ボタン・文字・画像・日付など)」の表と、レイアウトの図(図は、PowerPointで描いたチームもある)。
- **03 画面遷移図**: 画面どうしの矢印の図。
- **04 機能仕様書**: 「機能概要 / イベント / 処理内容」を、機能ごとに並べる。ソフト(スマホ)とハード(ラズパイ)で、シートを分ける。
- **05 ER図**: 図が中心(読み取れる文字は、見出しだけ)。
- **06 テーブル定義書**: テーブルごとに1シート。「No・論理名称・物理名称・データ型・桁数・初期値・PK・IDX・NN・備考」の表。
- **07 回路図**: 回路の図(部品の名前・数・規格・つなぎ方)。設計書類なので「外部設計」に入れる。機材購入リスト(品名・型番や規格・数・単価・小計・購入先・使う場所)は別の項目で、機材発注(11/5・12/1)のもとになる。
- **09 システム構成図**: 構成の図。
- **発表スライド(企画説明)**: 約16枚。表紙(「最終発表」)→ 作品を一言で → 内容 → 発案のきっかけ → 実演/操作説明の動画 → ペルソナ → 概要図 → モード説明 → ライバルと差別化 → メリット → マネタイズ(材料費・人件費・販売価格案・コストダウン案)→ 使用技術 → 今後の展望 → 終わり。ファイル名は「卒業制作展用企画説明」。
- **操作説明書**: PDFで1〜2ページ。実機の各部に番号を付けて説明し、Webアプリの操作を、番号つきの手順と図で示す。
- **アプリ説明動画**: mp4と、YouTubeの限定公開のURLを書いたテキストファイル(「限定公開URL」)。
- **シフト表**: 卒展の対応当番。10:00〜16:00を30分ごとの枠にして、担当者と休憩を書く。
- **ファイル名**: 「日付(YYMMDD)+成果物の名前+_チーム記号」が多いが、そろっていない(日付なし、チーム記号なしもある)。

### 叩き台に反映したこと
- 項目の「やること・できあがり」を、上の用紙の形(画面ごとに1シート、改訂日・改訂者、機能概要・イベント・処理内容、機材購入リストつきの回路図)に合わせた。
- 発表スライドの構成から、「ペルソナ」「費用の見積もり(材料費・開発費・人件費)」「今後の展望」の項目を足した(なければ点検で注意が出る)。
- **ER図とテーブル定義書は、「データを保存する場合」だけ必要なので、なくても注意だけにした**(最初は、ソフト系だけ必須としていたが、ハード系のチームにも、データを保存するものがあった)。回路図は、ハード系の企画で必要のまま。
- ハード系の見本(`docs/wbs-drafts/example-hard.md`)を足した(回路図と機材購入リスト・発注2回・組み立てを入れた。データを保存する前提で、ER図とテーブル定義書も入れた)。
- 「アプリ説明用スライド」は、サンプルの「卒業制作展用企画説明」のような題名(「企画説明」)でも成果物とみなす。
- **発表スライドとアプリ説明用スライドは別のもの(2026-10-26 確認)**。発表スライド=最終報告用。企画・背景から詳細に発表し、成果をすべて報告する。アプリ説明用スライド=卒展のブースで来場者に説明する簡易的なもの。
