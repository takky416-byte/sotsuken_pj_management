# 作業ログリマインド (Apps Script + Gmail)

授業日に、作業ログが未提出の学生へ、**あなたの Gmail から**リマインドを送ります。無料で、サーバーは要りません。

## 仕組み

| 項目 | 内容 |
|---|---|
| 送る時刻 | 火・水 (3-4限の日): **16:30ごろ** / 木 (1-2限の日): **10:45ごろ** (前後15分ずれることがある。Apps Script の仕様) |
| 対象 | キックオフ済みのチームの学生で、**その日の作業ログが未提出**の人。提出済み・**欠席**・キックオフ前のチーム・教員は対象外。「一言のない項目だけ」は未提出扱い(アプリと同じ基準) |
| 送らない日 | 授業日でない日、作業ログの運用開始日 (既定 10/28) より前、同じ日の同じ時間帯に送信済みのとき |
| 試験モード (初期値) | 学生には送らず、**あなた宛に1通だけ**「この人たちに、この文面で送ります」と送る |
| 本番モード | 未提出の学生に送り、あなたにも結果を送る (未提出が0名のときは、何も送らない) |
| 安全装置 | 二重送信の防止 / 送信先が40名を超えたら、送らずに止めて、あなたに知らせる |

データは、Firestore の REST API を、**あなたの Google アカウントの権限**で読みます (プロジェクトのオーナーなので読めます)。

## セットアップ (約15分)

1. <https://script.google.com> を、**学校のアカウント**で開き、「新しいプロジェクト」を作る。名前は「卒研PJ リマインド」など。
2. 左の「⚙ プロジェクトの設定」→「『appsscript.json』マニフェスト ファイルをエディタで表示する」にチェック。エディタに戻って、`appsscript.json` の中身を、このフォルダの `appsscript.json` に**置き換える**。
3. `コード.gs` の中身を、このフォルダの `Code.js` に**置き換える**。左の「＋」→「スクリプト」で、名前を `core` にして、`core.js` の中身を貼る。
4. 「プロジェクトの設定」→「Google Cloud Platform (GCP) プロジェクト」→「プロジェクトを変更」で、プロジェクト番号 **`348998571230`** (Firebase の `sotsuken-pj`) を入力する。
   - これをしないと、「Cloud Firestore API has not been used in project …」というエラーになります。
   - 「OAuth 同意画面」の設定を求められたら、ユーザーの種類は「内部」(学校のアカウントのみ)を選び、アプリ名とメールアドレスを入れて保存します。
5. **予行演習**: 関数 `dryRunAfternoon` を選んで「実行」。最初に権限の承認を求められるので、承認する(「このアプリは確認されていません」と出たら、「詳細」→「(プロジェクト名)に移動」。自分で作ったスクリプトなので問題ありません)。
   - 「実行ログ」に、`対象: N名` と、送る相手が出ます。**メールは送りません。**
   - 今日が授業日でない場合は、スクリプト プロパティに `DATE_OVERRIDE` = `2026-10-28` のように授業日を入れて試せます(火・水の日は `dryRunAfternoon`、木曜の日は `dryRunMorning`)。**`DATE_OVERRIDE` があるあいだは、MODE にかかわらず、必ず試験モード(あなた宛だけ)で動き、「送信済み」の記録も残しません。** 終わったら、`DATE_OVERRIDE` を削除してください(消し忘れても、本番のトリガーは、この間は学生に送りません)。
6. **トリガーを作る**: 関数 `setup` を実行。左の「トリガー」に、`remindMorning` と `remindAfternoon` ができます。このとき `MODE` は `test` (試験モード)になります。
7. **試験モードで確認**: 授業日の16:30ごろ(木曜は10:45ごろ)に、あなた宛に `[試験] 作業ログリマインドの送信予定` が届くか確認します。すぐ試したいときは、`DATE_OVERRIDE` を授業日(10/28など)にして、`remindAfternoon` を手動で実行します(後述の「手動で実行する手順」)。
8. 文面と対象に問題がなければ、関数 **`goLive`** を実行 → 学生に届くようになります。戻すときは `goTest`。止めるときは、「トリガー」から2つを削除します。

## 毎日のバックアップ (Google ドライブ)

全データを、毎日 3 時ごろ、あなたの Google ドライブの「**バックアップ**」フォルダ(ID は `Code.js` の `BACKUP_FOLDER_ID`。変えるときはスクリプト プロパティ `BACKUP_FOLDER_ID`)に、JSON で保存します(アプリの「設定」→「書き出し・バックアップ」と同じ形式。教員メモとアクセス履歴を含みます)。直近 60 日ぶんを残し、古いものはごみ箱へ移します(日数は、スクリプト プロパティ `BACKUP_KEEP`)。

1. `appsscript.json` を更新します(ドライブの権限が増えました)。左の ⚙ プロジェクトの設定 →「"appsscript.json" マニフェスト ファイルをエディタで表示する」にチェック → `appsscript.json` を、リポジトリの `apps-script/appsscript.json` の内容に置き換えます。`Code.js` も、最新の内容に置き換えます。
2. 関数 **`setupBackup`** を実行(権限の承認を求められます。ドライブの権限を許可)。トリガーができ、その場で 1 回、バックアップします。
3. ドライブの「バックアップ」フォルダに、`sotsuken-backup-日付.json` ができたことを確認します。
   - **このフォルダは、共有を「制限付き」にしてください**(「リンクを知っている全員」や学校のドメイン全員だと、学生にも見えます)。共有されていると、安全のため、バックアップを保存せず、あなたにメールで知らせます。
4. 失敗したときは、あなたに `[卒研PJ管理] 毎日のバックアップに失敗しました` というメールが届きます。
5. 復元は、アプリの「設定」→「書き出し・バックアップ」の「バックアップから復元する」で、このファイルを選びます。

バックアップのファイルには、学生のメールアドレスと教員メモが含まれます。フォルダは共有しないでください。読み取りは、1日あたりデータの件数ぶん(数千件)です。

## ミーティング録音 → 要旨 (Gemini)

進捗ミーティングの録音から、要旨の**下書き**を作ります。下書きは**先生だけ**が見られます。アプリの「チーム」→ チーム →「ミーティング記録」で確認・修正して、「学生に公開」を押すと、学生のホームの「前回のミーティングの要旨」に出ます(公開するまで、学生には見えません)。

| 項目 | 内容 |
|---|---|
| 録音の渡し方 | ドライブの「ミーティング録音」フォルダに、ファイルを入れる。名前は **`A_2026-10-28.m4a`** のように「チーム_日付」。日付がないときは、ファイルを入れた日になる |
| 形式・大きさ | m4a / mp3 / wav / aac / ogg / flac。**15MB まで** (10分ほどの m4a なら、約 5MB)。超えるときは、失敗として知らせる |
| 動くとき | 30 分おき (トリガー)。手動でも、関数 `summarizeRecordings` で動かせる |
| できるもの | 要旨・決まったこと・次の1週間でやること・詰まり・「聞き取れなかった点」。AI が「話されたことだけ」を書くように指示している。評価や、個人的な話は入れない指示 |
| 録音のその後 | 要旨ができたら、フォルダの中の「**処理済み**」に移す(**消さない**。先生だけが見られる) |
| 失敗したとき | あなたにメール。録音は、そのまま残る。同じ日・同じチームの要旨(下書き・公開済み)がすでにあるときも、上書きせずに知らせる。直したら、ファイルの「説明」(詳細パネル)を空にすると、もう一度試す |

### セットアップ

1. ドライブに、**録音を入れるフォルダ**を作る(例: 「ミーティング録音」)。**共有は「制限付き」のまま**にする(「リンクを知っている全員」や学校の全員だと、学生に聞こえてしまうので、動かない作りです)。フォルダの URL の末尾が、フォルダ ID。
2. **Gemini の API キー**を作る: <https://aistudio.google.com/apikey>。
   - **学生の声を含む録音を、外部の AI に送ります。** Google の規約では、無料枠で送った内容が、製品の改善に使われることがあり、有料枠(請求先アカウントを設定したプロジェクト)では使われない、とされています。**有料枠のプロジェクトのキーを使う**ことをおすすめします(使う量は少なく、月に数十円〜数百円の見込みです)。最新の規約を、ご自身で確認してください。
   - 初回の案内に、「録音して、AIで要旨を作ることがある」と書いてあります(学生は、案内を確認してから使い始めます)。
3. Apps Script の「プロジェクトの設定」→「スクリプト プロパティ」に、次を追加する。
   - `MEETING_AUDIO_FOLDER_ID` = 録音フォルダの ID
   - `GEMINI_API_KEY` = 作ったキー
   - (任意) `GEMINI_MODEL` = 使うモデル名(既定 `gemini-2.5-flash`。モデルが終了したときは、ここで変える)
4. エディタの「＋」→「スクリプト」で、名前を `summary` にして、`summary.js` の中身を貼る。`Code.js` も、最新の内容に置き換える(`core.js` と `appsscript.json` は、変更なし)。
5. **試す**: 短い録音(1分ほど)を、`A_<今日の日付>.m4a` の名前で、録音フォルダに入れる。関数 **`summarizeRecordings`** を実行する(初回は、権限の承認を求められる)。→ アプリで、チーム A の「ミーティング記録」に、下書きが出ることを確認する。→ 録音が「処理済み」に移っていることを確認する。
6. 関数 **`setupMeetingSummary`** を実行 → 30 分おきのトリガーができる。止めるときは、「トリガー」から `summarizeRecordings` を削除する。

> **確認できていること / できていないこと**: ファイル名・形式の判定、AI の返事の読み取り、Firestore への下書きの書き込み、失敗時の動き、上書きしない・二重に処理しない、は、自動テストで確認しています(AI とドライブの呼び出しは、模擬です)。**本物の Gemini への呼び出し(モデル名・m4a の受け付け・要旨の質)と、ドライブ・トリガー・メールは、Apps Script の中でしか確認できません。手順5で、必ず確認してください。** 要旨の質は、録音の音質に左右されます(発言者の区別は、AI には難しいことがあります)。

## こんなとき

| 症状 | 対処 |
|---|---|
| `Firestore 403` | 手順4のプロジェクトの変更を確認。あなたが Firebase プロジェクトのオーナーか確認 |
| `Cloud Firestore API has not been used in project …` | 手順4 (GCP プロジェクトを `348998571230` に) |
| メールが届かない | 迷惑メールフォルダ。学校のメールの受信制限。1日の送信上限 (Workspace は約1,500通) |
| 同じ日に、もう一度送りたい | スクリプト プロパティの `LAST_SENT` を削除 |
| 録音の要旨ができない | メールの内容を見る。ファイル名(チーム_日付)、15MB 以下、フォルダが「制限付き」、`GEMINI_API_KEY`。直したら、録音ファイルの「説明」を空にして、もう一度 |
| 送る相手が想定と違う | `dryRun…` のログで確認。作業ログの「欠席」は教員が入力します (アプリの「欠席」) |

## 確認できていること / できていないこと

- **確認済み (自動テスト)**: 判定のロジック (誰に送るか・送らない日・上限)、文面、Firestore の REST API からの読み取り (エミュレータに対して、このスクリプトをそのまま実行)、試験/本番モードの切り替え、二重送信の防止。
- **Apps Script の中でしか確認できない**: 権限の承認 (OAuth)、トリガーの起動、Gmail への実際の送信、本番の Firestore との接続。**手順5〜7で、本番に切り替える前に、必ず確認してください。**

## 手動で実行する手順 (予行演習で、あなた宛にメールを送る)

1. スクリプトのエディタで、左の **⚙ プロジェクトの設定** を開き、下へスクロールして「**スクリプト プロパティ**」→「スクリプト プロパティを追加」。
   - プロパティ: `DATE_OVERRIDE` / 値: `2026-10-28` (火・水の日)、木曜の午前を試すなら `2026-10-29` → 「スクリプト プロパティを保存」。
   - 作業ログの運用開始日(既定 10/28)より前の日付は、「運用開始日より前です」となり、送りません。
2. 左の **< > エディタ** に戻り、上の関数のプルダウンで **`remindAfternoon`** (木曜なら `remindMorning`) を選んで「**実行**」。
3. 下の「実行ログ」に、`予行演習です…` と `対象: N名` が出ます。しばらくすると、あなたのメールに `[試験] 作業ログリマインドの送信予定 (2026-10-28 午後)` が届きます。
4. **終わったら、`DATE_OVERRIDE` を削除**します (プロパティの右のごみ箱)。
